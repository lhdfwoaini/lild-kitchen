# Lil D Home Kitchen

我的个人食谱。记录真正做过的菜，保留实拍与人生第一次独立做菜的记忆，也留下下次做饭的小抄。

当前视觉是“暖白画布上的彩色个人食谱卡”：无衬线粗体、横向食物封面、整块橙/森林绿/酸橙绿主题。桌面1100px及以上为三列，平板与390px手机两列，窄屏及放大文字自然回到单列；详情的食材与步骤保持暖白阅读区。共三道在用菜谱，不恢复已归档的意面。

设计与维护统一记录在 `docs/维护规范.md`。`index.html` 为入口；`assets/site.css` 和 `assets/site.js` 是源文件，`assets/recipes.js` 由 `data/recipes.json` 与图片映射生成，不能直接编辑。每道菜可配置 `theme`，新增菜未指定时按稳定ID获得可复现主题，不随排序变化。

## 怎样打开

推荐双击根目录 **`一键预览.cmd`**。它自动构建、检查并启动本机预览，然后打开浏览器，无需敲命令。

预览为 `http://127.0.0.1:4177/kitchen/`，仅本机可访问，不是上线地址。目前三道菜为空气炸锅牛扒、平底锅煎牛排、打抛猪肉碎饭，对应 `#recipe-001`、`#recipe-003`、`#recipe-004`，可直接打开/刷新。稳定ID不重编号；前台展示编号则按当前有效列表自动生成001、002、003，新增/删除/调整顺序后自动顺延，首页与详情一致。浏览器前进、后退、返回列表都可用。快食意大利面已移除展示，原始记录与照片保留归档，旧详情链接返回食谱列表。

已生成的 `index.html` 也保留离线打开能力（没有 fetch/CDN）；日常仍推荐一键预览，可自动刷新构建。当前已通过 HTTP 子路径的实际验收，未把静态推断写成 file 协议实测。

## 以后只需要做两件事

1. 把照片放入 `图片/原图/菜名/`。已有菜放原来的菜名文件夹；新菜创建新文件夹。无需改文件名，不必处理大小或 EXIF。
2. 告诉我菜名、用过哪些食材、实际制作顺序、照片属于哪道菜。时间/温度/分量知道多少说多少；纪念或个人备注可选。没有做法的照片只暂存为草稿，不自动编成正式食谱。

示例：照片放进“番茄炒蛋”了。食材有……，我的实际做法是……，请更新并发布。没有新实拍时也可以先提供真实做法，明确标注的示意封面不会冒充照片。


## 文件位置

| 位置 | 用途 |
|---|---|
| `图片/原图/菜名/` | 你唯一需要管理的图片入口；保留原始文件，不公开 |
| `图片/展示图/` | 自动生成的 640/1200 WebP，已清理定位等元数据 |
| `data/recipes.json` | 唯一食谱数据，由 Codex 维护 |
| `data/images.json` | 封面、补图、实拍/AI来源映射 |
| `assets/` | 样式、交互、生成的数据与图标 |
| `scripts/` | 增量处理、预览、检查、打包与发布 |
| `.agents/skills/lild-kitchen-update/` | 食谱专用技能，纳入本项目 Git |
| `dist/` | 可直接部署的静态发布包，不含原图、备份或维护资料 |
| `.local/` | 本地母版、归档、扫描、截图和测试证据，不公开 |

空气炸锅牛扒的封面为 **AI 重绘展示图**，详情中的两张照片为 **实拍记录**。平底锅煎牛排、打抛猪肉碎饭暂无实拍，封面是根据实际做法制作的 **AI 生成示意图**，页面注明“非实拍”。2026-11-12定向优化使用内置imagegen重做三张原生4:3横向封面，统一暖白桌面、横向餐盘、柔光和饱满的食物尺度；输出1200×900、640×480 WebP，与卡片及详情窗口比例一致，不再出现方图两侧的空白带。没有拉伸图片或加滤镜，原图与旧母版均保留；快食意大利面的图片不进入发布包。没有使用外部图库。图像来源与可复用提示词见 `docs/图片来源与提示词.md`。

## 原版如何恢复

改造前网页与三张原图保存在 `.local/backups/before-redesign-20261111/original.zip`，内容已与原文件指纹核对。

详细更新约定、状态及验收证据见 `docs/维护规范.md`。你无需手工维护数据、HTML 或 Git。
