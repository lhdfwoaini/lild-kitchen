# Lil D Home Kitchen

我的个人食谱。记录真正做过的菜，保留实拍与人生第一次独立做菜的记忆，也留下下次做饭的小抄。

## 怎样打开

推荐双击根目录 **`一键预览.cmd`**。它自动构建、检查并启动本机预览，然后打开浏览器，无需敲命令。

预览为 `http://127.0.0.1:4177/kitchen/`，仅本机可访问，不是上线地址。两道详情可直接用 `#recipe-001`、`#recipe-002` 打开/刷新。浏览器前进、后退、返回列表都可用。

已生成的 `index.html` 也保留离线打开能力（没有 fetch/CDN）；日常仍推荐一键预览，可自动刷新构建。当前已通过 HTTP 子路径的实际验收，未把静态推断写成 file 协议实测。

## 以后只需要做两件事

1. 把照片放入 `图片/原图/菜名/`。已有菜放原来的菜名文件夹；新菜创建新文件夹。无需改文件名，不必处理大小或 EXIF。
2. 告诉我菜名、用过哪些食材、实际制作顺序、照片属于哪道菜。时间/温度/分量知道多少说多少；纪念或个人备注可选。没有做法的照片只暂存为草稿，不自动编成正式食谱。

示例：照片放进“番茄炒蛋”了。这是第三次独立做菜，食材有……，我的实际做法是……，请更新并发布。

## 两条更新命令

在本项目打开 Codex，使用项目技能 `.agents/skills/lild-kitchen-update/SKILL.md`：

```text
$lild-kitchen-update 扫描新增照片并预览变更，不发布
```

```text
$lild-kitchen-update 更新并发布食谱网站
```

首次新增技能后，如当前任务的技能选择器还没列出它，在本项目新开任务或直接指出以上 SKILL.md 路径即可。仅预览允许可恢复的本地更新，不会提交或上线。

## 文件位置

| 位置 | 用途 |
|---|---|
| `图片/原图/菜名/` | 你唯一需要管理的图片入口；保留原始文件，不公开 |
| `图片/展示图/` | 自动生成的 640/1200 WebP，已清理定位等元数据 |
| `data/recipes.json` | 唯一食谱数据，由 Codex 维护 |
| `data/images.json` | 封面、补图、实拍/AI来源映射 |
| `assets/` | 样式、交互、生成的数据与图标 |
| `scripts/` | 增量处理、预览、检查、打包与发布 |
| `.agents/skills/lild-kitchen-update/` | 食谱专用技能，纳入本项目 Git |
| `dist/` | 可直接部署的静态发布包，不含原图、备份或维护资料 |
| `.local/` | 本地母版、归档、扫描、截图和测试证据，不公开 |

两张菜品封面均为 **AI 重绘展示图**，详情中的三张照片为 **实拍记录**。没有使用外部图库。图像来源与可复用提示词见 `docs/图片来源与提示词.md`。

## 原版如何恢复

改造前网页与三张原图保存在 `.local/backups/before-redesign-20261111/original.zip`，内容已与原文件指纹核对。

将它解压到一个新的空文件夹，双击其中 `index.html` 即可查看完整原版；不要直接覆盖现有项目。之后每次更新的可恢复快照在 `.local/backups/update-*.zip`。原图仍在 `图片/原图/` 中，以原文件名、原字节保存。

详细更新约定、状态及验收证据见 `docs/维护规范.md`。你无需手工维护数据、HTML 或 Git。
