## 数据与状态

- recipes.json：id、number、status（ready/draft/archived）、name、subtitle、description、sourceFolder、method、time（label/scope/minutes）、ingredients、steps、package、record、note、quick、cover、photos，以及可选视觉字段 theme。只有 ready 导出到网站；archived 为用户要求移除的历史记录，保留原图、稳定ID和文字，不自动重新上架。时间 scope 区分煮面与整段烹饪。未给出的字段不猜。
- images.json：稳定图片ID、所属菜谱、源路径、kind（real/ai/external）、alt、label、focus；实拍重绘登记同菜的真实 references/promptId，无实拍的AI示意图登记 basis=recipe/promptId、不能伪造 references；外部 license 必须登记。

- `.local/reports/check.json`：静态检查。`.local/qa/browser.json`：当前发布文件指纹及三种宽度的真实交互证据。
- `data/release-check.json`：实际浏览器通过且亲眼复核截图后才记录 visualReview，CI 比对当前发布指纹，不接受过期凭证。

- data/drafts.json：本地待补做法，永不导出到正式列表。

## 图片规范

当前三张封面母版为原生4:3横向构图，横向餐盘、完整食物、暖白桌面与自然柔光。卡片和详情主图均为4:3窗口，使用 cover 贴合等比例图像，不进行主体强裁或拉伸，不再以方图 contain 留出左右空白带。优先在制图阶段协调盘子、食物尺度与画幅，不能为铺满添加配料；不改实拍的原始比例。现有母版1448×1086，脚本输出640×480/1200×900 WebP（质量84），应用 EXIF 方向并移除元数据。原图和旧母版永久保留；新母版仅在 `.local/generated/`，只处理源指纹变化的图片，不重复生成或重采样。

新菜没有AI工具时可直接用实拍，正确标注；没有实拍但允许生成时根据真实文字制作示意图，页面显示“AI 生成示意图 / 非实拍”。两者均不可用时提供明确待补占位并补齐类型支持，不阻塞真实文字录入。不要为统一版式补配料或杜撰做法。没有实拍的 photos 为空数组，不展示空实拍栏目。

## 运行与发布

一般顺序：backup → scan → agent补充真实文字/封面 → sync → build → check → pack → validate-browser → 人工目视 → release-check → export --require-qa → publish。

Python入口 `pwsh -NoProfile -File scripts/kitchen.ps1 scan`（命令可替换）。自动寻找本机 Codex 配套 Python/Pillow，fallback 为系统 Python；不安装 npm 包。浏览器检查用配套 Playwright 和已安装 Chrome，保留 Chromium sandbox，只服务 dist 到本机回环地址、阻止页面外网请求。

预览 `node scripts/preview.cjs` 或根目录一键入口；默认 `/kitchen/` 用于验证仓库子路径，部署时相对引用自动适应真实仓库名。退出命令服务可按 Ctrl+C；一键入口的后台服务不会开终端窗口，日志在 `.local/preview*.log`。

本次已按明确授权创建专用公开仓库 `lhdfwoaini/lild-kitchen`（ID 1453537714），Git 根就是食谱目录，origin 为 `https://github.com/lhdfwoaini/lild-kitchen.git`，分支 main，站点 `https://lhdfwoaini.github.io/lild-kitchen/`，Pages API 已设置 build_type=workflow。以后只更新这个仓库，不重复建仓库，不改上级项目远程。`lildphotos`、`street-corner-darkroom`、`thesis-doctor` 均为禁止发布目标。

`kitchen.config.json` 的 repository 必须为 owner/name，siteUrl 必须匹配默认 Pages 子路径。发布脚本先核实 GitHub 登录为 lhdfwoaini；支持现有 gh 登录，或用官方 Git credential helper 取用系统中已有的 github.com 登录，仅在进程内供 GitHub CLI 使用，不打印、不写入项目或配置。Git push 沿用系统凭据管理器；没有现成登录时报告并请用户完成 gh auth login，不抓取浏览器会话或读取凭据文件。

`publish.py` 无参数仅预检；`--execute` 必须有本轮发布授权、已审查本轮文件范围，并保留不相关改动。Codex审查后将具体文件路径数组写入 `.local/release-files.json`（不能放目录）；脚本校验 origin、分支、远端关系、QA，按该清单及白名单双重核对暂存，不用 git add .，推送一次后最多等待约3分钟。Pages失败或超时不推进基线；稍后 `--verify-only` 核对已推送提交及其成功工作流。若自动执行需超过工具等待窗口，使用保留会话并持续报告进度。

CI只导出已压缩图，不需要本地原图/AI母版：`node scripts/export.mjs --require-qa`。不新增CNAME，不改域名，不自动更换食谱仓库。回退优先正常 git revert 某次发布，再检查与部署，不 reset --hard，不 force push。

发布成功后运行 `node scripts/validate-browser.cjs --online`：从配置中的真实 Pages 子路径打开全部详情，检查刷新、前后退、速查、弹窗、图片、脚本和404，证据保存 `.local/qa-online/`。此模式只允许该站点来源的资源，不使用已有浏览器登录会话。只有工作流成功、文件指纹一致并且公网实际交互通过后，才向用户报告上线完成。
