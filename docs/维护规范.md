## 实际复用来源

已读取摄影项目 `J:\codex帮我从0到1搞钱\摄影展示网页\.agents\skills\lild-photos-update\SKILL.md`、`references/更新规范.md` 及其六个脚本：photo_common.py、scan_photos.py、extract_site_data.cjs、validate_site.py、validate_browser.cjs、test_incremental.py；核实摄影 origin 为 `lhdfwoaini/lildphotos.git`，读取其现有发布清单与项目约定。摄影文件和技能均未修改。

## 数据与状态

- recipes.json：id、number、status（ready/draft）、name、subtitle、description、sourceFolder、method、time（label/scope/minutes）、ingredients、steps、package、record、note、quick、cover、photos。时间 scope 区分煮面与整段烹饪。未给出的字段不猜。
- images.json：稳定图片ID、所属菜谱、源路径、kind（real/ai/external）、alt、label、focus；AI references/promptId、外部 license 必须登记。
- 本地处理记录.json：源指纹、处理版本、派生图指纹与尺寸，phase=generated。不代表已部署。
- `.local/reports/check.json`：静态检查。`.local/qa/browser.json`：当前发布文件指纹及三种宽度的真实交互证据。
- `data/release-check.json`：实际浏览器通过且亲眼复核截图后才记录 visualReview，CI 比对当前发布指纹，不接受过期凭证。
- `data/已发布照片清单.json`：初始 never-deployed。仅 `publish.py` 线上逐文件核验成功后写 deployed、commit、files、sources、images、recipes。不能用扫描清单覆盖它。
- data/drafts.json：本地待补做法，永不导出到正式列表。

## 图片规范

封面1:1，完整盘碗轮廓，自然柔光，暖白背景，真实食材；实拍保留完整比例。脚本先应用 EXIF 方向，再创建无元数据副本，以长边640/1200、WebP质量84输出。没有变化不重采样。原图永久不写回；AI原始输出仅存在 `.local/generated/`，无需重复请求。

新菜没有AI工具时可直接用实拍，正确标注；不应为统一版式补配料或杜撰做法。参考截图本轮并未实际提供，因此未声称复刻截图。

## 运行与发布

一般顺序：backup → scan → agent补充真实文字/封面 → sync → build → check → pack → validate-browser → 人工目视 → release-check → export --require-qa → publish。

Python入口 `pwsh -NoProfile -File scripts/kitchen.ps1 scan`（命令可替换）。自动寻找本机 Codex 配套 Python/Pillow，fallback 为系统 Python；不安装 npm 包。浏览器检查用配套 Playwright 和已安装 Chrome，保留 Chromium sandbox，只服务 dist 到本机回环地址、阻止页面外网请求。

预览 `node scripts/preview.cjs` 或根目录一键入口；默认 `/kitchen/` 用于验证仓库子路径，部署时相对引用自动适应真实仓库名。退出命令服务可按 Ctrl+C；一键入口的后台服务不会开终端窗口，日志在 `.local/preview*.log`。

首次发布需要经用户确认的独立仓库、写权限和其 GitHub Pages Actions 设置。`kitchen.config.json` 的 repository 必须为 owner/name，siteUrl 必须匹配默认 Pages 子路径，branch为main；不能使用摄影仓库。使用 GitHub App 检查权限及仓库，二进制图片推送走本机 Git 认证；不要读/输出凭据文件。

`publish.py` 无参数仅预检；`--execute` 必须有本轮发布授权、已审查本轮文件范围，并保留不相关改动。Codex审查后将具体文件路径数组写入 `.local/release-files.json`（不能放目录）；脚本校验 origin、分支、远端关系、QA，按该清单及白名单双重核对暂存，不用 git add .，推送一次后最多等待约3分钟。Pages失败或超时不推进基线；稍后 `--verify-only` 核对已推送提交及其成功工作流。若自动执行需超过工具等待窗口，使用保留会话并持续报告进度。

CI只导出已压缩图，不需要本地原图/AI母版：`node scripts/export.mjs --require-qa`。不新增CNAME，不改域名；未经确认不创建远端仓库。回退优先正常 git revert 某次发布，再检查与部署，不 reset --hard，不 force push。
